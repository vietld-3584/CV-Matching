# フィールド対応表（入力 → 出力）

`plan-project` Skillが3つの出力ファイルの各セクションをどの入力から埋めるかの対応表。**すべての項目について、まず文書からの抽出を試み、それでも埋まらない項目のみヒアリング（`hearing.md`）に回す**。

凡例：📄=提案書、🗒️=プロジェクト概要（クライアントブリーフ）、💰=見積書、💵=コストシート、💬=ヒアリング必須

## 文書からは絶対に取れず、常にヒアリングが必要な項目（まとめ）

- プロジェクトコード（社内slug）
- コミュニケーション手段／チケット管理ツール（overview.md §3・stakeholders.md §5共通）
- クライアント側・Sun*側の実名・連絡先（stakeholders.md §1・§2の欠落分）
- 意思決定・承認フロー、エスカレーションフロー（stakeholders.md §3・§4）
- D/C/Q/Sトレードオフの14pt配分、および各カテゴリのMemo（overview.md §6）
- KPIの具体的な数値（提案書の記載が定性的な場合）
- 対応範囲・役割分担の作業項目ごとの実施者、および双方が対応しないスコープ（overview.md §4。提案書に記載があっても契約形態とセットで必ず確認質問を挟む）
