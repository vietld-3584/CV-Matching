# 非機能要件 AIドラフト提案カタログ

`non-function-list.md` §2「カテゴリの目安」の8カテゴリごとに、ユーザーが数値目標を出せない場合にAIがどんな根拠からドラフトを提案するかをまとめる。**すべて「ドラフト（要確認）」として提示し、ユーザーの承認を得てから確定値にする**（無断で数値を確定しない）。

根拠として参照する情報源：`docs/02_requirements/project-overview.md`（対象プラットフォーム・サービス概要）、`docs/01_management/overview.md`（契約制約・想定規模）、提案書／プロジェクト概要（クライアントブリーフ）、ヒアリング内容。

## 性能

**着眼点**: 対象プラットフォーム（Web/モバイル/業務システム）、想定同時アクセス数、リアルタイム性の要否。

**ドラフト例**:
- 一般的なWeb管理画面 → 「一覧・詳細画面の表示は3秒以内」
- 検索・一覧が主要機能 → 「検索結果の表示は3秒以内（99パーセンタイル5秒以内）」
- 根拠が薄い場合は具体的な秒数を出さず、「性能目標は運用開始後の実測を踏まえて別途設定」と提案し空欄のまま残す選択肢も示す

## 可用性

**着眼点**: 業務システム（社内向け・平日日中のみ稼働でよいか）かtoC向け（24/365稼働が前提か）、契約書に稼働率SLAの記載があるか。

**ドラフト例**:
- 社内業務システム → 「稼働率 99%程度（計画停止・保守を除く）、RTO 1営業日、RPO 24時間」
- toC向けサービス → 「稼働率 99.5%程度、RTO/RPO は障害影響範囲に応じて別途協議」

## セキュリティ

**着眼点**: 個人情報・決済情報・医療情報等の機密データを扱うか、外部公開か社内限定か。

**ドラフト例**:
- 個人情報（メール・氏名等）を扱うWebサービス → 「通信のTLS化必須、パスワードのハッシュ化保存、個人情報へのアクセスは権限を持つロールのみ」
- 決済情報を扱う → 「PCI DSS等の該当ガイドライン準拠を検討事項として明記（詳細は別途セキュリティ設計で確定）」
- 社内限定システムで機密度が低い → 「基本的な認証・認可のみで可、詳細は運用担当と協議」

## 拡張性

**着眼点**: 将来のトラフィック増加見込み、機能追加の見込み（提案書のロードマップ記載等）。

**ドラフト例**:
- 明確な将来計画が提案書にある場合 → その記載をそのままドラフト化して確認を取る
- 記載がない場合 → 「現時点では明確な拡張計画はなし。将来的な機能追加を想定した設計とするかは別途協議」として空欄含みで提示

## 運用・保守性

**着眼点**: 運用体制（Sun*側が運用まで担うか、クライアントに引き渡すか）、監視・アラート体制の有無（`overview.md`のコミュニケーション手段・体制情報を参照）。

**ドラフト例**:
- Sun*側が運用も担う契約 → 「エラーログの記録・監視、障害発生時のアラート通知」
- 開発のみでクライアントに引き渡す契約 → 「運用手順書・デプロイ手順の整備をもって完了とし、監視体制はクライアント側で別途構築」

## 互換性

**着眼点**: 対象プラットフォーム（`project-overview.md`）に記載のブラウザ・OS・デバイス。クライアント社内の標準環境（提案書に記載があれば）。

**ドラフト例**:
- Web → 「最新版のChrome/Safari/Edgeを対象。IE11等の古いブラウザは対象外」（要確認）
- モバイル → 「iOS/Androidの直近2バージョンを対象」

## 法令・規制

**着眼点**: 個人情報を扱うか（個人情報保護法）、業界特有の規制（医療・金融・教育等）があるか。

**ドラフト例**:
- 個人情報を扱う → 「個人情報保護法に基づく適切な取得・利用・保管」
- 特定業界規制がありそうな場合 → 該当する可能性のある規制名を挙げつつ「詳細はクライアント側の法務確認が必要」と明記し、AIが規制の有無を断定しない

## データ管理

**着眼点**: データの重要度（消えたら業務が止まるか）、想定データ保持期間（提案書・契約期間からの推測）。

**ドラフト例**:
- 一般的な業務データ → 「日次バックアップ、契約期間中＋α（例：契約終了後1年）のデータ保持」
- 重要度が高いデータ（決済履歴等） → 「バックアップ頻度・保持期間をより厳格に設定することを提案し、具体的な数値はクライアント確認が必要」と明記

## 提示時の共通ルール

- 各カテゴリのドラフトは「〇〇という理解でよいか、それとも別の基準があるか」の確認形式で提示する
- ユーザーが「わからない・後で決める」と回答した場合は、目標値・基準セルを空欄のまま残し、Skill実行の完了サマリで未確定事項として報告する（AIが独断で数値を埋めない）
- 該当性が低いカテゴリ（例：社内ツールで法令・規制の懸念がほぼない）は、対象外である旨を一言添えて省略してよい
