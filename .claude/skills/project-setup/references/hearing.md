# ヒアリング詳細（Q1〜Q4）

各質問の **問いかけ方の例**、**選択肢**、**回答の解釈ルール** をまとめる。
Skill はここを参照して、1 質問 1 ターンで会話を進める。

## 共通ルール

- 番号選択ではなく **キーワードで例示** する
- 自然言語の回答を許容する（曖昧な場合は確認質問を返す）
- 解釈に揺らぎがあれば必ず「○○として解釈しましたが合っていますか？」と確認する

## Q1: チーム役割（複数選択）

| `DevOps` | DevOps / SRE | 「DevOps」「SRE」「インフラ」 |
| `Other` | その他 | 上記に当てはまらないとき |

## Q3-1: 通知媒体（単一選択）

**問いかけ例**:
> セッション完了などのタイミングで通知を受け取りたい媒体はありますか？
> 不要 / Slack / Discord / Telegram から 1 つ選んでください。

**選択肢キー**:

| キー | ラベル |
|------|--------|
| `none` | 不要 |
| `slack` | Slack |
| `discord` | Discord |
| `telegram` | Telegram |

> `none` 以外を選んだ場合、`.claude/settings.local.json` に通知 hook が登録される。
> 環境変数（webhook URL 等）は別途 `.env` で設定する必要がある旨を案内する。

## Q3-2: 外部 MCP（複数選択 + 自由記述）

**問いかけ例**:
> 利用したい外部 MCP サーバーはありますか？
> 既知のもの: momorph（フロント設計） / playwright（E2E） / context7（ドキュメント検索）
> その他の MCP サーバーがあれば名前を教えてください。

**選択肢キー（predefined）**: `momorph` / `playwright` / `context7`

**自由記述（custom）**:
- ユーザーが他の MCP 名を出した場合、Skill は **context7 / Web 検索で正式な command / args を調べる**
- 調べて分かれば `mcp.custom` に完成形 `{ name, type, command, args, env }` で追記
- 調べても不明な場合のみ `{ name: "...", command: "TODO", args: [], note: "未確認 — 手動で埋めてください" }` の雛形を残し、ユーザーに修正依頼

> momorph 選択時は `rules/momorph/` と `skills/momorph-implement-design/` も自動で同梱される（メモランダム §5-3）。

## Q4: 追加要望（自由記述）

**問いかけ例（Step 4 末尾で）**:
> 以下を取得します（取得物表を提示）。
> ここに記載がない作業で、AI にやらせたい作業はありますか？

**回答の扱い**:
- 空 → そのまま完了サマリへ
- 内容あり → `.setup-state.json` の `q4` に保存。Step 6（Q4 後処理）で `/tkm:find-skill` と `skill-creator` を駆使して追加 Skill を配置する
