# タスク一覧

> 本ドキュメントは、実際のタスク（詳細な作業内容・サブタスク・コメント）が記録されている GitHub Issue へのポインタと、その**現在のステータスを一覧で素早く確認するための集約ビュー**です。
> タスクの詳細な議論・仕様・進捗コメントは GitHub Issue 側に記載し、本ファイルには重複して転記しないでください。
> [`schedule.md`](./schedule.md) の WBS（Epic/Story）とは粒度が異なります。Epic/Story レベルの計画・進捗は `schedule.md` / [`progress.md`](./progress.md) を参照してください。本ファイルはその配下にある個々の実作業タスク単位の一覧です。
> **PM・AIエージェントは、タスクに着手する際・完了した際に、都度本ファイルの該当行（ステータス・着手日/完了日・更新日）を更新してください。**

## 2. ステータスの定義

| ステータス | 定義 |
| --- | --- |
| 未着手 | GitHub Issue は登録済みだが、まだ着手していない |
| 進行中 | 着手済みで、作業が進んでいる |
| レビュー中 | 作業は完了し、レビュー・承認待ちの状態（例: PRレビュー中） |
| 完了 | レビュー・承認まで完了し、Issue がクローズ済み |
| 保留 | 依存関係・意思決定待ち等の理由で作業を中断している（理由は「コメント」欄に記載） |

## 3. 運用ルール

- タスクの詳細（作業内容・仕様・サブタスク・議論の経緯）は GitHub Issue 側で管理し、本ファイルには転記しません。本ファイルはステータス確認のための集約ビューです。
- タスクに着手する際は、都度ステータスを「進行中」に変更し、着手日・更新日を記載してください。
- タスクが完了した際は、ステータスを「完了」に変更し、完了日・更新日を記載してください。
- 新しい GitHub Issue が作成された場合は、都度本ファイルに行を追加してください。対応する WBS（Epic/Story）が [`schedule.md`](./schedule.md) にあればID を記載し、なければ空欄のままで構いません。
- 保留・ブロッカーが発生した場合は、ステータスを「保留」にし、理由を「コメント」欄に記載してください。恒常的な課題として扱う場合は [`risks-problems/problem-list.md`](./risks-problems/problem-list.md) にも登録してください。
