# 完了の定義 (Definition of Done)

> 本ドキュメントは、本プロジェクトにおける「完了（Done）」を具体的な基準として定義し、自社（Sun*）・クライアント双方で事前に合意するためのものです。
> 各基準は [`overview.md`](./overview.md) の「2. プロジェクトKPI・成功基準」、[`../02_requirements/function-list.md`](../02_requirements/function-list.md)、[`../02_requirements/non-function-list.md`](../02_requirements/non-function-list.md) の内容と対応付けてください。
> **プロジェクトのクロージング時には本ドキュメントを更新し、全基準が100%達成されているかを確認してください。** 未達成の基準がある場合は、クライアントの合意を得てスコープ除外（waive）とするか、次フェーズへ持出しとするかを判断し、その経緯・理由・承認者を本ドキュメントに記録してください。

## 2. カテゴリの目安

<!-- プロジェクトの特性に応じて追加・調整してください -->

| カテゴリ | 説明 |
| --- | --- |
| 機能要件 | function-list.md に定義された機能が仕様通り動作すること |
| 非機能要件（品質・性能） | non-function-list.md に定義された性能・セキュリティ等の基準を満たすこと |
| ドキュメント・成果物 | 契約上の成果物（設計書、マニュアル等）が納品されていること |
| テスト・受入 | 単体/結合/受入テストが完了し、合格していること |
| 運用移行・引き継ぎ | 運用手順・監視・保守体制がクライアント側に引き継がれていること |
| 契約・請求 | 契約範囲の作業が完了し、請求・検収処理が完了していること |

## 3. ステータス・判定基準

<!-- ステータスの定義。プロジェクトの特性に応じて調整してください -->

| ステータス | 定義 |
| --- | --- |
| 達成 | 基準を完全に満たし、エビデンスで確認済み |
| 一部達成 | 基準の一部は満たすが、残課題がある（残課題は problem-list.md に登録） |
| 未達成 | 基準を満たしていない |

<!-- 未達成・一部達成の基準に対する判断フロー。承認権限は stakeholders.md の「3. 意思決定・承認フロー」に準拠してください -->

**未達成時の対応フロー:**
1. Sun* 側（PM）が対応方針（対応して達成／スコープ除外(waive)／次フェーズへ持出し）を提案し、理由を記載する。
2. クライアント側の意思決定者（[`stakeholders.md`](./stakeholders.md) 参照）がレビュー・承認する。
3. 除外・持出しが承認された場合、その理由・承認者・承認日を「1. 完了の定義一覧」に記録する。
4. 対応方針の検討過程で重要な決定が生じた場合は [`decision.md`](./decision.md) にも記録する。
